# 路线图

## 每个项目的标配

用这个模板创建的项目，默认都会交付这几样：

| 模块 | 说明 | 状态 |
|------|------|------|
| **桌面端（Electron）** | 开发、三平台打包、自动更新、可插拔功能 | 已完成 |
| **文档网站（Docusaurus）** | 落地页 + 使用说明 + SEO，GitHub Pages 部署 | 已完成 |
| **网页端（Web）** | 复用 React UI 层，Vite 构建 | 规划中 |
| **小程序端（Mini）** | 复用核心逻辑，UI 走小程序框架 | 规划中 |

## 跨端架构一句话

**核心与壳分离**：真正的产品逻辑住在共享核心（`app/shared`、功能包的 `src/shared`）；桌面 / 网页 / 小程序各是一个"壳"，只负责渲染 + 平台能力。

换端 = 换壳，不重写核心。详见[架构概览](./architecture)。

## 当前进度

- 桌面端可插拔功能体系稳定：`pnpm feature:new` 加工具、`enabledFeatures` 开关。
- 文档网站上线：落地页 + 中文使用说明 + 英文核心文档 + SEO。
- 网页端 / 小程序端的目录与能力接口已按 ADR-004 预留。

## 接下来

1. **网页端**：抽出"能力抽象层"，用 Vite 建 `app/web` 壳复用 `app/renderer`；桌面专属能力在网页端降级或隐藏。
2. **小程序端**：用 Taro / uni-app 建 `app/mini`，功能包 `shared` 逻辑直接复用，UI 重写。
3. 每加一端，补该端的构建 / 打包 / 发布到 CI，并更新本文档。

> 详细规范见仓库根 `docs/project-standards.md`。
